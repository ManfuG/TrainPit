# TrainPit agent context

- Product/repository: TrainPit, `ManfuG/TrainPit`. This is a working Android application, not the old initialization-only scaffold. Keep code and repository text in English.
- UI: Overview shows today's workout and an interactive body-weight trend; point selection shows weekday/date/value. Workout logging groups compact kg/reps rows by exercise; Add set explicitly copies the last row, blank exercises are not actual results. Plans shows only the current weekly schedule. History uses same-row client/record filters, distinct plan/session/weight colors, no IDs/deleted toggle/duplicate titles, and actual per-exercise daily max-load/rep-total charts. Keep copy concise, the purple/red/orange palette, and sync/status out of the header. Preserve consent/destructive warnings.
- Stack: Kotlin 2.4.21, AGP 9.5.0, Gradle 9.6.0, JVM 17, compile/target SDK 37, minSdk 26. Versions live in `gradle/libs.versions.toml`; Android CLI package name is `platforms;android-37.0`, with `build-tools;36.0.0`.
- Four modules only: `app` composes `core:model`, `core:data`, and `core:sync`. Data/sync depend only on model; model is pure Kotlin/JVM. Use existing Compose/Material 3, ViewModel/StateFlow, Room/KSP, WorkManager, and Firebase patterns; no DI framework or extra modules without a demonstrated need.
- Read `docs/DATA_MODEL.md`, `docs/ROLES_AND_PRIVACY.md`, `docs/SYNCHRONIZATION.md`, and `docs/FIREBASE.md` before changing persistence, authorization, archives, or transport.
- Firebase project `trainpit-9ab42`: email/password Auth and Firestore, billing disabled. Public `app/google-services.json` is intentional. Never enable paid services, Functions, or Storage to bypass free quotas.
- Room is authoritative offline. Sensitive row values are encrypted with per-account Android Keystore keys; Firestore persistent disk caching is disabled. Preserve the shared reference-counted repository, transactional cursor commits, bounded processing, unchanged-metadata fast paths, and single-flight Firebase synchronization.
- Domain entries are immutable signed revisions. Schema-1 signing bytes remain byte-identical; schema 2 adds nonempty signed `slotParents` for cross-root natural-slot resolution. Preserve same-root `parents`, same-owner/client/kind/slot cross-root checks, all causal dependencies, tombstones, divergent heads, integer grams and calendar dates; never wall-clock LWW. Old apps must update before receiving schema-2 resolutions.
- One plan per trainer/client/Monday week and one weight per client/date. Rootless saves correct existing slots; explicit restoration descends from a tombstone, stale edits and occupied moves reject. Trainer-owned idempotent rollover clones only the latest unambiguous active-client plan, retains exercise IDs, skips deleted/conflicted slots, and fast-paths unchanged history. Clients may project the signed prior schedule into the current week without fabricating trainer records. Keep session plan references exact.
- Trainer access requires an active client-approved relationship; body weight has separate client-controlled consent. Purge foreign local records when revocation is learned, while preserving owned records. Trainer is not a global administrator.
- Cloud payloads are readable to Firebase/project administrators, not end-to-end encrypted. Archives use PBKDF2/AES-GCM and original ECDSA record signatures; archive-provided keys do not establish identity, and the declared exporter is not separately signed. Anyone with a file/password can decrypt it. Do not synchronize database files or claim remote secure erasure.
- Keep health drafts/passwords in memory, not saved state. Preserve `ArchiveDraft` lifetime and stable ActivityResult/navigation keys across the credential relock after a long Android file-picker operation. Clear account-specific UI on Firebase Auth UID changes.
- Local erasure must retain a repository reference before Auth sign-out clears controller ownership, cancel work, invalidate shared handles, remove database files and destroy keys. No destructive migration/key-loss fallback.
